# Auto-Media — Optional n8n Integration

## Role

n8n is an optional automation engine.

Auto-Media must work normally without n8n.

Use n8n when a custom workflow is useful or when the operator wants to import a workflow generated by ChatGPT or another workflow authoring tool.

## Optional integration state

Support:
- n8n disabled
- n8n configured but idle
- n8n connected
- n8n connection error

The UI should clearly show whether n8n is available.

## Job invocation

For automations whose execution mode is n8n, Auto-Media creates a job and sends a webhook payload.

~~~json
{
  "jobId": "job_123",
  "profileId": "future-tech",
  "contentTypeId": "custom-video",
  "automationId": "automation_456"
}
~~~

n8n may request additional non-secret configuration from Auto-Media.

## Callback

n8n calls the authenticated Auto-Media callback endpoint with:
- job ID
- status
- generated content
- media references
- errors where applicable

## Universal workflow rule

An n8n workflow must not hard-code:
- page IDs
- account IDs
- page prompts
- access tokens
- passwords

The workflow receives IDs and uses the Auto-Media runtime contract.

## Existing Future Tech workflow

The current workflow logic can become either:
1. a native Auto-Media Tech News Image automation, or
2. an optional n8n workflow template.

The long-term architecture should prefer native built-in execution for common patterns and retain n8n for advanced/custom cases.

## n8n JSON import

Auto-Media accepts exported n8n JSON and validates:
1. syntax
2. workflow structure
3. node compatibility
4. credential requirements
5. expected runtime inputs
6. expected outputs
7. embedded-secret risk
8. test result

Never silently execute an imported workflow.

## Docker

If n8n is enabled, deploy it as a separate container in the same Docker Compose network.

Example service-to-service address:

http://n8n:5678

Auto-Media can remain the primary user-facing website while n8n is an implementation detail or an advanced workspace tool.
